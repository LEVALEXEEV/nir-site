# three.js vs react-three-fiber

Сайт с результатами НИР: сравнение производительности двух способов рендеринга
3D в браузере — императивного **three.js** и декларативного
**react-three-fiber (R3F)**. Сравниваются способы управления одной и той же
сценой: сцена описана один раз, стенд перед каждой серией сверяет кадры всех
реализаций.

!!! abstract "Главное"
    * **При нагрузке на GPU R3F не дороже three.js** — различие в пределах ±5%.
    * **Частые обновления:** R3F с рекомендованной архитектурой (ref) не быстрее
      three.js; антипаттерн `setState` каждый кадр — в 2,7–3 раза медленнее.
    * **Старт:** бандл R3F больше в ≈2,1 раза, первый кадр позже в 1,3–2,2 раза.

## Сценарии

| ID | Сцена | Что измеряется |
|----|-------|----------------|
| S1 | TorusKnot, PBR, тени; свип нагрузки A–D | время кадра, GPU-время |
| S2 | 3000 анимируемых Box | время кадра, p99, фазы |
| S3 | 100 статичных TorusKnot, холодная загрузка | время до первого кадра, бандл |
| S4 | 2000 Box, клик → подсветка | задержка ввода по фазам |
| S5 | анимация S2, N от 100 до 51 200 | ёмкость при 60 / 30 FPS |
